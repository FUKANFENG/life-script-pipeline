# Infinite Canvas 多轮 Demo 实验档案

> 记录范围：当前线程中可见的 Infinite Canvas 部署、模型接入、画布创作、局域网修复和本地超分实验，以及仓库中能够核验的产物。未写入 API Key、访问令牌或其他敏感凭据。

## 上下文锚点

- 项目：Infinite Canvas 本地 Web UI 与 Canvas Agent。
- 代码仓库：`FUKANFENG/life-script-pipeline`，默认分支 `main`；本地工作分支为 `local/xg-v0.12.0`。
- 本地项目目录：`work/infinite-canvas`。
- 典型服务：Web UI `3000`、Canvas Agent `17371`、本地适配服务按项目配置监听；局域网使用时 Web UI 绑定 `0.0.0.0`，资源地址不能写死为 `127.0.0.1`。
- 归档原则：画布保留目标、参考图、分析、提示词、模型、生成结果、质检、失败和返工路径；本地输出保留源图、过程文件、最终图、日志、哈希和指标。

## 用户原始提问

本线程围绕以下目标展开：先部署并理解 Infinite Canvas，再把 Codex、MiniMax、ChatGPT Bridge Image、ChatGPT Workflow Bridge 等能力接入画布；在画布中完成故事、品牌和商品视觉 Demo；遇到失败时排查适配层、资源地址和局域网访问；最后使用本地超分提升画质，并把实验过程、代码和资产备份下来，便于回顾和复用。

## 结论与决策

1. Infinite Canvas 负责画布交互、节点关系和导演台编排；真实的生图、生视频、生音频和分析能力由配置的模型 API 或本地适配器提供。
2. Codex 的作用是连接 Canvas Agent、理解画布状态、创建和修改节点、组织提示词与调用流程；它本身不是视频模型，也不会凭空替代视频后端。
3. 外部模型应通过稳定的适配层接入。画布只需要识别生成、分析、任务状态和资产回填等稳定能力，视频任务必须按异步 job 处理。
4. 图片生成结果需要写入持久化资产目录，并在画布中使用可被局域网其他设备访问的相对或局域网地址；不能把浏览器会话级 `blob:` URL 或本机 `127.0.0.1` 当作共享资产地址。
5. 本线程验证出的默认超分流程为：`RealESRGAN_x4plus` 原生 4 倍、`tile=0` 整图推理，再用 Lanczos 回落到原图 2 倍。它用于增强边缘和纹理，不负责修复生成模型的语义、文字或人物结构错误。
6. 代码和流程文档进入 GitHub；图片、原图、中间图、最终图和运行日志单独做资产备份，不把大体积二进制误混进代码提交。

## 实验记录

### 实验 1：Infinite Canvas 部署、源码理解与 Codex 接入

**目标**：在本地运行无限画布，理解项目结构，并确认 Codex 接入的职责边界。

**过程**：

- 运行 Web UI，打开画布路由并确认节点、提示词输入、模型选择、参考图和结果节点可用。
- 阅读 README、Canvas Agent 与前端连接逻辑，确认项目是“画布 + Agent + 模型适配”的组合，而不是单一生图模型。
- 将 Codex 连接到 Canvas Agent。Codex 可以读取画布语义、创建节点、组织节点关系、调用工作流和回填结果。
- 形成“导演台前端 / Canvas Agent / AI Gateway 或 Bridge / 具体模型服务”的分层理解。

**结果**：Codex 接入后最直接的价值是自动化操作画布和编排流程；它能调用已配置的图片、文字、音频或视频接口，但不会因为接入 Codex 就自动获得视频生成能力。

**可复用结论**：后续新增模型时优先增加适配器或通道配置，不要把上游 API 细节散落在画布组件里。

### 实验 2：MiniMax 多模态能力接入方向验证

**目标**：根据 MiniMax API 文档，把图片、音频、视频和文本模型纳入画布的模型选择与任务流程。

**过程**：

- 梳理 MiniMax API 的文本、图像、视频、语音/音频入口和异步任务模式。
- 将模型通道按能力分类，避免把“模型名”误当成“画布能力”；图片、视频、音频分别需要不同的请求体、结果地址和轮询逻辑。
- 通过统一适配层让画布选择模型，适配器负责将画布参数转换为 MiniMax 请求，并把输出变成持久化资产。
- 对视频任务保留 `job_id -> status -> output` 的状态链，避免把异步视频误处理为同步图片。

**结果**：画布具备选择外部模型的结构基础，但模型是否能真正生成仍取决于 API Key、网络、额度、请求契约、回调/轮询和资产落盘是否都正确。凭据不写入仓库、Notion 或备份包。

**可复用结论**：新增模型时要同时记录模型能力、请求格式、异步状态、错误映射、文件落盘和局域网 URL，不能只增加一个下拉选项。

### 实验 3：ChatGPT Bridge Image 02 接入与失败排查

**目标**：让画布可以选择自封装的 `ChatGPT Bridge Image 02` 生成图片。

**过程**：

- 在模型选择中加入 `ChatGPT Bridge Image 02`，画布侧能够显示该模型。
- 首次调用出现“全部图片生成失败”，随后出现 `Failed to fetch`。
- 从现象判断，画布节点本身已经进入生成流程，问题应优先排查 Bridge 端点可达性、CORS/局域网地址、请求契约、返回 JSON 与持久化资产 URL，而不是只重试前端节点。
- 后续将更完整的 ChatGPT Workflow Bridge v0.6.0 接入到统一工作流中，保留生成、分析、质检和资产回填的路径。

**结果**：模型选择层接入成功，但早期单独 Bridge 路径出现失败；线程可见记录不足以把某一个具体原因写成已完全证实的根因。可确认的工程结论是：必须使用统一适配层、明确错误信息和可访问的持久化 URL，不能只在下拉菜单中注册模型。

**可复用结论**：生成失败时按“前端请求 -> Bridge/API -> 上游模型 -> 文件落盘 -> 资源 URL -> 画布回填”逐段定位，并把上游错误正文写进任务日志。

### 实验 4：60 秒故事 Demo 与图片/视频差异

**目标**：在无限画布中构造约 60 秒的故事，并验证图片分镜到视频的生产链路。

**过程**：

- 在画布中建立故事节点和多个分镜节点，生成多张连续画面。
- 首版主要得到静态图片，播放时表现为图片切换，类似 PPT，而不是连续视频。
- 进一步确认：静态图片生成和视频生成是两条不同能力链。要得到短视频，必须选择视频模型、提交异步任务、轮询完成并把视频资产写回画布。
- 因视频模型额度/次数和任务耗时有限，实验中只适合挑选最有必要的镜头做视频验证，不能把“图片生成成功”当作“视频生成成功”。

**结果**：故事编排和静态分镜链路可用；视频部分需要独立的视频适配器与异步任务状态，不能用图片节点代替。

**可复用结论**：画布模板必须明确标注 `image`、`video`、`audio` 类型，并为每类资产保留不同的预览、状态和失败重试逻辑。

### 实验 5：Florae Noctis 香氛系列四图

**目标**：用一张 3:4 参考海报，在画布中完成系列化香水视觉图。

**流程**：

1. 新建独立画布并导入参考图，保留原始总提示词。
2. 用 ChatGPT Workflow Pro 拆解构图、版式、标题层级、留白、材质、光线和固定英文。
3. 将分析结果压缩成 A-D 四行变量矩阵，固定画幅、瓶身形象、标题层级、底部 `HERBARIUM` 与暗调沙龙光线。
4. 使用 ChatGPT Bridge Image 02 生成四条图生图分支：琥珀、幽苔、夜澜、暮绛。
5. 用 GPT Pro 逐张检查版式、产品形象、中文二字标题、英文标题、留白和道具；结果 `4/4 PASS`。
6. 通过持久化资产地址提取源 PNG，使用 RealESRGAN 4x 整图推理和 Lanczos 2x 交付。

**结果**：源图 `1086x1448`，交付图 `2172x2896`。RealESRGAN 约 26.407 秒，Lanczos 与写盘约 24.387 秒。四张均有源图、最终图、日志、联系表、`manifest.csv` 和复盘文档。

**关键经验**：系列一致性依赖“固定视觉锁定项 + 受控变量矩阵”，不能让四条提示词完全自由改写。小号装饰文字仍不适合作为印刷级可编辑文字，正式交付需在排版软件中覆盖。

**产物**：`outputs/florae-noctis-series`、`outputs/florae-noctis-perfume-demo-2026-07-14`。

### 实验 6：青岚品牌包装展示 Demo

**目标**：验证从品牌规范、单品系列到宽幅全物料主视觉的画布工作流。

**流程**：

1. 在画布中建立品牌母版，固定森林绿、玉石绿、青瓷灰绿、宋体骨架、浅金工艺和产品摄影语言。
2. 先生成茶叶礼盒，再将其作为视觉锚点，生成茶叶罐、手提袋、纸杯、茶饮杯、名片、香薰蜡烛和线香。
3. 选择代表性单品作为参考，生成 `21:9` 全物料展示图。
4. 使用 ChatGPT Workflow Pro 做 A/B/G 三批质检。单品首轮通过；全物料首版因小物料分类不清判定 FAIL，再定向返工为 `G01-R1` 并通过。
5. 统一使用 RealESRGAN 4x `tile=0`，再 Lanczos 回落到 2x。

**结果**：8 张 `3:4` 单品图和 1 张 `21:9` 全物料图；所有最终图完成超分。单品交付 `2172x2896`，宽幅交付 `3832x1642`。九图平均回缩 PSNR `36.347 dB`、SSIM `0.9543`。

**关键经验**：质检必须逐项核对产品类别、品牌字样、比例和布局；全物料图“整体好看”不等于小物料都可辨识。首版 FAIL 和返工路径要保留，便于后续做模板。

**产物**：`outputs/qinglan-brand`、`outputs/qinglan-brand-demo-2026-07-14`。

### 实验 7：超现实梦境 8 镜头分镜

**目标**：按用户给定的八个梦境场景生成统一色调的 `16:9` 分镜组图。

**内容**：流沙中的破碎石膏头像、环形光环、失重廊柱、倒置沙丘建筑、深海夜空巨鲸、漂浮石膏像、发光珊瑚和通往云端的螺旋阶梯。

**约束**：暖赭粉低饱和、橙粉体积光、冷色只用于远景阴影、低对比度、细颗粒、轻雾化长曝光光晕、35mm 透视、深景深、统一 LUT；使用图片 3.0，比例 `16:9`。

**结果**：8 张原始分镜保存在 `outputs/surreal-dream-storyboard`，对应 8 张 2x 超分图保存在 `outputs/surreal-dream-storyboard-upscaled-x2`。文件名使用 `S01` 至 `S08` 保持叙事顺序。

**关键经验**：将统一风格约束放在每一条镜头提示词中，并把镜头主体、人物位置、远景留白和光线作为固定字段，能减少组图之间的漂移。

### 实验 8：女孩与巨熊北欧绘本 8 镜头

**目标**：用熊和女孩参考图，在无限画布中生成 `9:16`、角色一致、统一色调的 8 张故事绘本分镜，并完成顺序化超分交付。

**流程**：

1. 新建画布，导入巨熊和女孩角色参考图。
2. 建立“女孩、巨熊、低饱和棕灰、灰蓝点缀、北欧峡湾冰川、柔光漫射、手绘水彩、四个大远景留白”的全局风格约束。
3. 在画布中按故事顺序生成 S01-S08，保留提示词、参考关系和结果节点。
4. 对源图做复制和顺序命名，不覆盖原始 Bridge 资产。
5. 使用 `RealESRGAN_x4plus -s 4 -t 0` 生成 4x 中间图，再 Lanczos 回落到相对源图 2x，最终文件统一使用 `S01` 至 `S08` 前缀。

**结果**：8/8 成功；源图统一 `941x1672`，4x 中间图 `3764x6688`，最终图 `1882x3344`。RealESRGAN 累计 `69.119s`，Lanczos 与 PNG 写盘 `37.053s`，批次总耗时 `106.597s`。校验结果：平均回缩 PSNR `37.4205 dB`，SSIM `0.950414`，平均 RGB 绝对差 `2.5352`；S01、S04、S07 视觉抽检 PASS，未发现切块接缝、明暗方块、硬光晕或明显语义变化。

**产物**：`outputs/girl-bear-nordic-storybook-upscaled-x2`，其中包含源图、4x 中间图、最终图、日志、`upscale_manifest.json`、`validation.json` 和复盘文档。

### 实验 9：商品/品牌自动化流程设计

**目标**：把“上传一个商品图 -> 生成电商主图/详情图 -> 质检 -> 不通过重试 -> 交付”的流程沉淀为画布模板。

**设计**：

```text
商品参考图
  -> GPT Pro 分析商品、材质、视角和禁改项
  -> 生成结构化主图/详情图提示词
  -> 图生图生成候选
  -> GPT Pro 逐项检查商品一致性、构图、文字和电商规范
  -> PASS: 进入超分和交付
  -> FAIL: 带问题清单回到提示词节点定向重试
```

**验证状态**：画布流程和节点结构已明确，商品主图/详情图模板可以复用；本线程可核验的落盘成品主要是香氛和青岚品牌 Demo，因此不把尚未确认完成的草帽全流程写成已交付结果。

**关键经验**：参考图只负责锁定商品身份和不可改变项；文字模型负责提示词和检查清单；图像模型负责视觉生成；质检模型负责是否进入下一步。生成、质检、返工都要保留为画布节点。

### 实验 10：局域网服务与资产地址排查

**目标**：让局域网内其他设备可以打开 Web UI，并能接收到生成图片。

**过程与结论**：

- Web UI 需要监听 `0.0.0.0`，不能只绑定回环地址。
- 画布 Agent、Bridge 和 Web UI 的服务地址需要分开配置；浏览器端不能把本机 `127.0.0.1` 当作局域网服务器地址。
- 生成结果必须落盘到服务可提供的公共目录，前端使用相对路径或局域网主机名拼接 URL。
- 浏览器 `blob:` URL 只适合当前会话，不适合跨设备访问和长期归档。
- 排查顺序：服务监听 -> 防火墙/端口 -> API 请求 -> 文件落盘 -> HTTP 资源地址 -> 画布回填。

**结果**：局域网问题的核心不是把并发从 3 降到 1，而是修正资源的可达地址和服务监听范围；并发策略应由上游限流、重试和冷却机制决定，不能用来掩盖路径错误。
